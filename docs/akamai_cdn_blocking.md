# Документация: Проблема блокировки Akamai CDN и автоматизация SID-куки

## Проблема

Сайт business-standard.com использует **Akamai CDN** для защиты от ботов и автоматизированных запросов.
Akamai анализирует входящие запросы и блокирует те, которые исходят из:

1. **IP-адресов дата-центров** (облачные серверы, Docker-контейнеры на VPS)
2. **Headless-браузеров** (Chromium без пользовательского профиля)
3. **Подозрительных User-Agent** (отсутствие стандартных заголовков браузера)

При блокировке сайт возвращает HTTP 403 "Access Denied" вместо реального контента.∑

### Как это проявляется

```
# Запрос из Docker (дата-центр IP)
$ curl https://www.business-standard.com/latest-news
HTTP 403 - Access Denied

# Запрос с хост-машины (резидентный IP)
$ curl https://www.business-standard.com/latest-news
HTTP 200 - полный HTML контент
```

## Решение: Автоматизация SID-куки

### Что было раньше
Ранее для обхода cookie-баннера требовалось вручную:
1. Открыть сайт в браузере
2. Принять куки
3. Скопировать значение `_sid` из DevTools
4. Вставить в `.env` файл

### Что сейчас
[`SessionManager`](../scrap/web_input/session_manager.py) автоматически:
1. Запускает Chrome через Playwright
2. Открывает сайт и принимает куки
3. Извлекает `_sid` из cookie-контекста
4. Использует эту сессию для всех последующих запросов

Переменная `SID` в `.env` теперь **не обязательна**.

## Запуск

### С хост-машины (резидентный IP) — работает
```bash
make run-local
```

### Из Docker (дата-центр IP) — может не работать
```bash
make run
```
Если Akamai блокирует IP сервера, потребуется residential proxy (см. ниже).

## Residential Proxy — что это и как использовать

### Что такое Residential Proxy

Residential proxy — это прокси-сервер, который использует IP-адреса обычных
интернет-провайдеров (резидентные IP), а не IP дата-центров. Это позволяет
обойти блокировки CDN, так как запросы выглядят как обычные пользовательские.

### Популярные провайдеры

| Провайдер | Цена | Бесплатный тариф |
|-----------|------|-----------------|
| Bright Data | ~$10/GB | Нет |
| Oxylabs | ~$15/GB | Нет |
| Smartproxy | ~$7/GB | Нет |
| IPRoyal | ~$4/GB | 2 ГБ бесплатно |
| FreeProxyLists | Бесплатно | Да (ненадёжно) |

### Как настроить residential proxy в приложении

1. **Зарегистрируйтесь** у провайдера residential proxy
2. **Получите** данные подключения: `host`, `port`, `username`, `password`
3. **Добавьте** переменные окружения в `.env`:
   ```
   PROXY_HOST="proxy.provider.com"
   PROXY_PORT="8080"
   PROXY_USER="username"
   PROXY_PASS="password"
   ```
4. **SessionManager** автоматически использует прокси при запуске

### Пример конфигурации (IPRoyal)
```
PROXY_HOST="proxy.royalproxy.com"
PROXY_PORT="8080"
PROXY_USER="login"
PROXY_PASS="password"
```

### Альтернативные решения

1. **Запуск с домашнего компьютера** — если у вас резидентный IP, просто
   используйте `make run-local`
2. **VPS с резидентным IP** — некоторые провайдеры предлагают VPS с
   резидентными IP (дороже)
3. **Tor** — бесплатный, но медленный и часто блокируется
4. **VPN** — может помочь, но многие VPN-сети тоже в чёрном списке CDN

│                                                      │

│  3. Принятие cookie consent (3 стратегии)            │
